## 设计说明

### 一、如何确保 JSON 格式输出

整体采用 **"system prompt 强约束 + 代码兜底解析 + 失败自修复"** 三层策略:

1. **System prompt 内嵌 JSON Schema**: 把字段、类型、枚举值、示例值直接写在 system 里,
   让模型先"看到"目标结构再开口。
2. **`temperature=0`**: 关闭随机性,使同一输入复现同一输出。
3. **代码块包裹 + 正则提取**: 要求模型用 ```` ```json ... ``` ```` 包裹,
   `_strip_code_fence` 用正则抠出纯 JSON 串,避免前后多余文字干扰 `json.loads`。
4. **解析失败自修复**: 若 `json.loads` 抛错,把模型上一次的错输出和具体异常一起回传,
   让模型重新输出修正版本(只重试一次,避免死循环)。
5. **配合 max_tokens=2048**: 防止 JSON 被截断造成不闭合。

### 二、正向约束 (Positive Constraints) — 告诉模型"该怎么做"

| 序号 | 约束                                                                     | 目的                              |
| ---- | ------------------------------------------------------------------------ | --------------------------------- |
| 1    | 只输出一个 JSON 对象,用 ```json``` 代码块包裹                            | 便于正则提取,杜绝解释性文字       |
| 2    | 字符串双引号,中文保留中文                                                | 保证 `json.loads` 不报错          |
| 3    | 日期统一 ISO 格式 (`YYYY-MM-DD` / `YYYYMMDD`)                            | 便于后续时间序列对齐               |
| 4    | 数值字段为数字类型,单位通过字段名表达 (`change_bp`, `close`, ...)        | 让下游策略直接做数值运算           |
| 5    | factors 按原文出现顺序排列                                               | 便于人工 diff/校对                 |
| 6    | 每张卡必须带 `source_quote`                                              | 可追溯,降低幻觉风险               |
| 7    | `sentiment_score ∈ [-1, 1]` 保留一位小数                                 | 数值规整,便于聚合统计             |
| 8    | `cross_asset_summary` 中无数据的子项保留空对象 `{}`                      | 保证 Schema 稳定,下游键访问不报错 |

### 三、负向约束 (Negative Constraints) — 告诉模型"不准做什么"

| 序号 | 约束                                                       | 目的                                          |
| ---- | ---------------------------------------------------------- | --------------------------------------------- |
| 1    | 禁止输出 Schema 外字段、禁止改字段大小写                   | Schema 锁死                                   |
| 2    | 禁止编造原文中不存在的数字、机构、日期、言论               | 抑制幻觉                                      |
| 3    | 禁止将多个事件合并到同一张因子卡 (一事一卡)               | 保持原子性,方便后续聚合                       |
| 4    | 禁止使用 `null` / `None` / `NaN`,缺失数值不出键,缺失字符串用 `""` | 避免 JS/Python 端的 `null` 差异歧义 |
| 5    | 禁止在 JSON 中插入注释 (`//` `/* */`)                      | 保证标准 JSON 可解析                          |
| 6    | 禁止 markdown 标题/列表                                    | 防止污染输出                                  |
| 7    | 禁止把单位写进数值 (`"4.28%"` → `4.28`)                    | 数值字段保持纯数字                            |

### 四、本次笔试使用的大模型 / AI 工具

- **模型**: Claude (Anthropic) — 本代码默认使用 `claude-opus-4-7`
  (也可切换至 `claude-sonnet-4-6` / `claude-haiku-4-5-20251001` 在成本/速度/精度间权衡)。
- **调用方式**: 官方 `anthropic` Python SDK,`messages.create` 接口。
- **使用经验**:
  - 中文金融文本理解上,Claude 的指令跟随能力较强,
    在 `temperature=0` 下基本能稳定输出符合 Schema 的 JSON,数值/日期/枚举值很少出错。
  - 当 Schema 较复杂时,**在 system 里给一个完整字段注释表 + 一两条字段示例**
    比单纯描述要求收敛得更快。
  - 抑制幻觉的关键是强制 `source_quote`,模型一旦要写引语就会回到原文确认数值,
    显著降低数字编造。
  - 兜底层面再加 `json.loads` 失败自修复,几乎可以做到 100% 拿到合法 JSON。
